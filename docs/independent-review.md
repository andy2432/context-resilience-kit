# 独立复核

## 结论

两名隔离复核者分别进行了角色门对抗审查和公开发布审查。复核者不修改仓库、不访问网络、不执行发布。

初始复核发现了多项角色门绕过、安装路径错误、写入失败策略问题和发布文档缺口。修复后，角色复核者在当前快照上重新执行完整对抗集，15 个独立构造场景全部符合预期，未发现新的 P0/P1；发布复核者在当前快照上确认原技术缺陷已关闭。剩余发布元数据与独立复核文件缺口已按复核建议修正。

当前结论：本地技术门禁和独立复核通过，可以进入 GitHub 发布阶段。远程 CI 只有在公开推送后才会产生真实执行结果，不能提前视为已通过。

## 角色门复核

初始复核发现的失败模式：

- 自报 `intent` 可覆盖用户纠错；
- 任意存在文件可冒充派单证据；
- `read_file` 可读取 raw rollout；
- 验证命令可夹带搜索或输出重定向；
- `apply_patch` 文本可隐藏业务文件修改；
- 验收可读取多个证据；
- follow-on 调查可省略布尔标记；
- 请求可扩大摘要上限；
- 业务代码只读证据被误伤；
- 最小记忆为空话，resume 缺失任务/线程/验收事实；
- 任意 Node 脚本可利用 `test` 子串进入命令白名单。

修复后验证：

- 角色场景 `50/50` 通过；
- P0 场景 `35/35` 阻断；
- 角色门漏放 `0`；
- 文字规则基线漏放 `36`；
- 独立对抗集合 `15/15` 符合预期；
- 精确业务代码只读证据仍允许，最小验收未被过度阻断。

## 发布复核

初始发布复核发现的失败模式：

- 默认配置含平台或业务专属内容；
- 占位符按字符类解释而不是字面值；
- 安装说明与模板目录映射不一致；
- 空源 `--write` 仍报告成功；
- 测试数量和场景元数据漂移；
- 独立复核文件缺失；
- CI 未覆盖声明的 Node.js 最低版本。

修复后验证：

- B07 端到端安装映射通过；
- B08 空源写入失败关闭通过；
- B09 字面占位符匹配通过；
- 私有路径、真实线程 ID、业务词和高置信凭据扫描通过；
- CI 矩阵覆盖 Node.js `18.17.0` 和 `20`，以及 Ubuntu/Windows；
- `npm pack --dry-run` 包含许可证、README、安全、贡献、变更和技能入口。

## 残余风险

1. `--role` 是静态动作计划门。客户端必须实际在工具执行前调用它，才能阻止动作。
2. `node --test`、`npm test` 等测试运行器会执行仓库代码。静态门无法证明测试脚本无副作用；需要更强隔离时应使用只读文件系统、容器或独立验收环境。
3. 文本 secret 扫描是纵深防御，不替代专用 secret scanner。
4. 外部平台、生产版本和真实 CI 状态必须在发布后重新观测，不能借用本地报告替代。
