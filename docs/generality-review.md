# 通用性评审

## 结论

纠正后的来源审计已完成重新核验。旧报告把当前协调线程误当作历史线程，现已废弃，不再作为 Kit 的来源依据。Kit 只保留经过抽象的行为模式：精确角色绑定、派单优先、行动白名单、最小记忆、受限验收、证据指针和失败关闭。

公开仓库不包含来源项目的线程 ID、聊天原文、业务名词、联系信息、服务器地址、平台标识、生产状态或内部路径。示例、测试和报告均使用合成数据。

## 来源重新核验

| 核验项 | 结果 |
|---|---|
| 纠正版本存在且为当前源项目 HEAD | 通过 |
| 旧错误报告 | 标记为废弃，未用于本次通用化 |
| 产品事实是否变化 | 未变化；Kit 不复制具体业务事实 |
| 原始聊天是否进入公开仓库 | 否 |

具体来源数量、线程身份、排序和消息统计不进入公开仓库；公开产物只保留抽象结论和合成回归。

## 抽象映射

| 来源模式 | 通用机制 | 验证 |
|---|---|---|
| 只写“不写业务代码”仍会亲自调查 | 角色意图分类和 dispatch-first 硬门 | RD-01、RD-02、RD-09、RD-18 |
| 线程标题不能证明角色 | 精确 `threadId` 绑定，未知角色失败关闭 | RD-10、RD-17、RD-24 |
| 调查、历史扫描、日志解析容易占满主上下文 | 禁止开放式历史和代码探索 | RD-04、RD-05、RD-08 |
| 调试和实现可能从“帮忙看一下”滑入 | 协调者实现动作硬阻断 | RD-06、RD-07 |
| 验收容易扩成二次完整调查 | 命名证据和有限预算 | RD-11 至 RD-14、RD-20 |
| 长报告重新灌满主线程 | 20 行摘要上限和证据指针 | RD-19 |
| 压缩只保留窄规则 | 生成式角色卡和契约恢复 | RD-16 |
| 自报已派单不可信 | task/thread/evidence 必填 | RD-27 |
| 紧急措辞可能绕过职责 | 紧急意图仍要求派单 | RD-18 |
| 角色契约本身可能被改坏 | 授权引用、revision、派单顺序校验 | RD-26 和契约 schema |

## 已删除的项目专属内容

- 业务领域名词和产品规则。
- 真实线程 ID、标题、消息数量和排序标识。
- 聊天正文、原始 rollout、session 路径和全局状态文件路径。
- 真实源文件、commit、域名、账号、平台审核和生产版本。
- 特定外部平台、支付、隐私、备案或设备流程。
- 只对单一项目成立的目录结构、服务拓扑和测试命令。

## 适用边界

适用于需要跨压缩、交接或长时间协作保持事实和职责边界的软件仓库，尤其适合有协调者、调查者、实现者和验收者分工的 Codex 工作流。

不适合作为以下能力的替代品：

- 生产访问控制或密钥管理；
- 网络隔离、权限系统或沙箱；
- 专用 secret scanner；
- 外部平台真实状态核验；
- 法律、合规或业务正确性的最终判断。

静态 `--role` 只判定提交给它的动作计划。若客户端不在工具执行前调用角色门，必须通过项目指令、wrapper 或受信任 hook 接入；不得把“契约已存在”误称为“运行时已强制”。
