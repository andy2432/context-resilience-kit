# Repository Instructions

1. Run `npm test` before reporting completion.
2. Preserve the separation between current rules, append-only decisions, open work, release state, task evidence, role contract, and generated resume.
3. Add a failing deterministic scenario before weakening or expanding a hard gate.
4. Keep normal CLI output under 20 lines.
5. Do not add real chat records, credentials, customer data, internal infrastructure addresses, or project-specific production facts.
6. `--fast`, `--deep`, `--release`, and `--role` must remain read-only; `--write` may change only the configured recovery resume.
7. No context check may deploy, publish, spend money, or mutate production data.
